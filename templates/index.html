Queue Memory Representation (Linked Nodes & Pointers)

Live visualization of memory nodes, FRONT pointer, and REAR pointer.

FRONT Pointer: Always references the oldest order in the system. dequeue() takes O(1) time without shifting elements.
REAR Pointer: Always references the newest order entered. enqueue() links the new node in O(1) time.

Queue Algorithms Pseudocode

1. Enqueue Operation (Insertion at Rear) 
Algorithm Enqueue(Queue, order):
  1. newNode = new Node(order)
  2. if Queue.isEmpty():
         Queue.front = newNode
         Queue.rear = newNode
     else:
         Queue.rear.next = newNode
         Queue.rear = newNode
  3. Queue.size = Queue.size + 1
  4. return True  // Time: O(1)
2. Dequeue Operation (Removal from Front) 
Algorithm Dequeue(Queue):
  1. if Queue.isEmpty():
         throw QueueUnderflowError
  2. order = Queue.front.data
  3. Queue.front = Queue.front.next
  4. if Queue.front == NULL:
         Queue.rear = NULL
  5. Queue.size = Queue.size - 1
  6. return order  // Time: O(1)

1. Abstract & Problem Statement

Traditional food ordering systems in quick-service restaurants face customer dissatisfaction and unfair wait times when orders are fulfilled out of sequence. To ensure deterministic fairness and avoid starvation, this project implements an Online Food Order Processing System governed by a First-In-First-Out (FIFO) Queue Data Structure.

The system guarantees that incoming customer requests are placed at the REAR (Enqueue) and prepared by kitchen staff strictly from the FRONT (Dequeue). The platform features real-time order tracking with position countdowns, a digital Kitchen Display System (KDS), a public McDonald's-style pickup counter display, and an interactive DSA memory visualization lab.

3. Mini Project Viva Q&A Guide (For External Examiner)

Q1: Why is a Queue data structure chosen instead of a Stack for food order processing?

A Stack operates on LIFO (Last-In-First-Out), meaning the newest order placed would be cooked first, causing earlier customers to starve indefinitely. A Queue enforces FIFO (First-In-First-Out), ensuring every customer is served fairly in the exact order of arrival.

Q2: What is the time complexity of Enqueue and Dequeue in your implementation?

Both Enqueue and Dequeue achieve O(1) constant time complexity. Using explicit front and rear pointers, inserting at the tail requires no shifting, and removing from the head simply advances the front pointer.

Q3: What is "False Overflow" in linear queues and how is it prevented?

In fixed-array linear queues, as elements are dequeued, empty slots appear at the front, but the rear pointer may reach the array boundary, reporting queue full even with vacant space. In this project, we prevent this by utilizing a linked-node dynamic queue and providing a circular buffer module using modulo arithmetic (rear + 1) % capacity.

Q4: How does the system calculate dynamic wait times for waiting customers?

Wait time is computed dynamically based on the order's 1-based position in the queue: Estimated Wait = (Queue Position × Average Slot Time) + Recipe Prep Time. As earlier orders are dequeued, each waiting customer's position automatically decrements.

Q5: Where else are Queue data structures used in computer science?

Queues are ubiquitous: CPU Task Scheduling (Round Robin / FCFS), Operating System Print Spoolers, Breadth-First Search (BFS) graph traversals, Web Server asynchronous request handling (Nginx / RabbitMQ), and Network packet buffers.
